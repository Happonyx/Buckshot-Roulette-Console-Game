# Buckshot-Roulette-Console-Game
After developing my coding skills quite a bit, I decided to take on the challenge of programming a replica of the full game Buckshot Roulette in Java. I had to learn abstraction, inheritance, and packages I never knew existed to make it work.

* Important Note: currently, hard mode does not change the difficulty of the bots. It only affects whether hard mode items are added into the item pool. I plan on implementing this in the future, but for now, the bot(s) are always use the most advanced algorithm.

Functionality:
- The game prompts a title screen with options to customize the game
- Starting the game, you are given a set amount of items and lives
- If you shoot yourself with a blank, you keep your turn. In every other scenario, the shotgun is passed to the next person
- Items assist you in winning and do not waste a turn
- The main objective is to be the last one standing, whether it's against your friends or robots
- Winning grants you (completely useless) money
- Note: keywords are implemented for almost everything (ex: typing "mag" is a shortcut to use a magnifying glass)

When I originally started this project, I was very new to Java. The idea behind the game's creation was purely experimental; I didn't intend on creating more than the full game. The first version of the program was simple, messy, and hard to customize. Even so, I was extremely proud of it. A year later, I decided that I wanted to rewrite my code from scratch. I wanted to improve the game, add my own twists, and make it feel like an official project, rather than a test to my programming capabilities.

One of my biggest goals with making this project was sharing it with others. Many friends at my school get in trouble for playing "unblocked" games on websites that they shouldn't be on, so my idea was to program a game that my friends could play without getting in trouble. I was successful in it, too: with the newest version having multiplayer, new items, and completely customizable chances & values, the program was not only a lot more fun to play but also easier to play with friends.

I didn't make this program just for fun, though. I wanted to deepen my understanding of Java, solve problems I've never had to solve before, and dip my toes in concepts that seemed completely foreign. To make the game as efficient, customizable, and unique as possible, I went out of my way to learn the roots of inheritance and abstraction and how I could use it for items. Many versions later, I ended up with a clean skeleton that I could use to add items and program their functionality easily. 

This program also got me into commenting my own code. Previously, I hadn't really considered commenting your code as something vital, so I would never do it. The creation of this program made me understand how important comments truly are. It's extremely hard to rewrite code when you have to figure out what a block of code is doing; this was especially the case when starting the remake of the original. Comments also made the debugging process much easier. 

Out of all of my projects, this one is definitely the most organized, clean, and functional.
